1. What would happen if an ArrayList was used instead of a HashSet? Is there an advantage to using a HashSet here?

If we used an ArrayList instead of a HashSet, it would change how the tracker handles duplicates and lookup performance. A HashSet doesn’t allow duplicates automatically. So if we add a duplicate, the HashSet just ignores it. However, an ArrayList allows duplicates. This means that in order to handle duplicates, we would have to add additional code (Something like ```if (!list.contains(movie))```). Using an ArrayList would also increase the time to retrieve the movies the user has watched. This is because in our HashSet, the equals() method is overridden to allow us to instantly check if a movie exists by jumping directly to the movie's hash. However, with an ArrayList, we have to traverse the entire list, which takes O(n) rather than O(1). Another not-so-important difference is that the HashSet doesn’t preserve the order when saving and printing the movies, and an ArrayList does preserve the order in which the movies were added.

2. We chose: ```java HashMap<String, HashSet<Movie>>``` for the tracker, which made it very easy to answer questions such as "What movies has Alice watched" or "What is Alice's total viewing time". Explain how a different design, such as ```java HashMap<Movie, HashSet<String>>``` would make certain other questions very easy to answer and others more difficult.

Right now, we have the users as the keys (string) and the movies the user has watched as the value (set). In a HashSet, we can use the key to get the items in the set that the key points to. However, we cannot take an item in the set and get the key that points to it. It is a one-way system. So when we flip the value and the key, it drastically changes the way the system works. In our current method, the question “What movies has Alice watched?” is easy because we can use the key ```“alice"``` and immediately get the set of movies that Alice has watched (```watchedMovies.get("alice") → [Inception, Up, The Matrix]```). The question “What is Alice’s total viewing time?” would also be easy because you can easily find all of Alice’s movies and sum up their running time. However, things start getting hard and time-consuming when you want to search for something starting with the movie. For example, a question like “Who all has watched Inception?” would be hard because you cannot just use the movie Inception as a key to retrieve all the people that have watched it. You will have to traverse through all of the users and check their set to see if they have inception. This will take a very long time and is way harder compared to the other questions mentioned above. Same goes for if you ask a question like “What is the most popular movie?” This question requires you to traverse through every user and keep track of who all has seen each movie, then add it up to get the most-watched movie. 

If we switch the format to have the Movie as the key and the Users as the set, this essentially flips the time complexities and difficulties of the questions above. “What movies has Alice watched?” becomes a hard and time-consuming task. This is because now you have to traverse through every movie to check if ```“alice”``` is in the set. The same goes for the question “What is Alice’s total viewing time?” This also requires you to traverse through the whole list to get the movies she has watched, then add the times together. The question “Who all has watched Inception?” becomes easier and faster because now you can just plug in the key ```Inception``` and get the set of everyone who has watched it. The same goes for the question “How many people have watched the Matrix?” All you have to do is plug in the key ```Matrix``` and then add up the items in the list to get your answer.
